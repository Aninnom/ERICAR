# 3차선 회피·YOLO 분기

- 작업 브랜치: `feat/3lane-yolo-fork`, main 기반
- 기존 라이다 회피·차선 색 기반 차로 번호 사용. 0=오른쪽, 1=중앙, 2=왼쪽
- S2에서 장애물 회피 주행, YOLO `left` 또는 `right` 연속 확인 후 방향 저장
- 두 화살표 동시 확인 시 방향 확정 보류
- 조기 준비: 화살표 최소 면적 0.6% → 0.15%, 서로 다른 3프레임 같은 방향 확인. 초기값이며 실영상 보정 필요
- S2 방향 확정 전·분기 유지 중 속도 상한 0.18 m/s. 기존 기본 속도 0.4 m/s 접근 완화
- 최초 확정 방향·시각은 `control.fork_sign`, `fork_sign_stamp`에 기록. 이후 반대 검출로 방향 변경 없음
- 작은 표지판을 YOLO가 검출하지 않거나 지속적으로 반대로 분류하는 경우 로직만으로 교정 불가
- YOLO 확정 즉시 방향 기억. 장애물 없는 출구 정렬은 `fork_prepare_distance`(0.15 m) 전진 후 요청
- 준비 중에도 일반 라이다 회피 활성. 넓은 군집 분류 누락 시에도 실제 통로 점으로 장애물 판단
- 목표 쪽 빈 거리·안전 조향 확인 후 한 차로씩 이동. 목표 쪽 막힘 시 일반 장애물 회피, 최종 방향 유지
- 목표 끝 차로 도착 전 방향 기억 유지. 도착 후부터 `fork_distance` 차감, 소진 시 요청·목표 해제
- 구간 관리자 S3 진입 시 미완료 분기 기억도 해제, 다음 미션으로 목표 전파 방지
- 예전 `fork_wait_for_obstacles`·`fork_clear_distance` 설정은 미사용. 새 `fork_prepare_distance`로 짧은 준비 거리 설정
- A=차량 왼쪽(도면 아래), B=차량 오른쪽(도면 위). 끝 차로 정렬 후에만 출구 경계 보정 활성
- 중앙 부근에서 선택 출구로 꺾이는 노란 선은 교통섬 경계 후보: A의 오른쪽, B의 왼쪽 경계로 보정
- 두 선 간격이 차로 폭의 1.5배 초과 시 선택 출구 쪽 선 하나만 사용, 서로 다른 출구 선 평균 방지
- 보정은 영상 형상 휴리스틱. 실제 교통섬 인식·지도 좌표 추적 기능 아님, 동일 녹화 전후 비교 필요

## 검증

PC 상태 시험: `python ericar_driver/test/test_fork.py`

차에서 녹화 재생 전후 비교·회귀 시험 후 실차 시험 필요 (`docs/lane.md` 검증 순서).
상태 시험: 즉시 요청·방향 기억·요청 만료·목표 쪽 막힘 우회·A/B 교통섬 경계 BEV 목표점 확인.
BEV 시험은 단일 경계 형상 합성. 실제 카메라 원근 변환·교통섬 전체 분기 궤적 검증 미포함.

차에서 단독 시작: 센서·바퀴 실행 후 `ros2 launch ericar_driver driver.launch.py start_stage:=fork` 사용.
센서 실행은 `ros2 launch ericar_driver bringup.launch.py driver:=false record:=true` 사용.
모델 클래스는 `left`, `right` 포함 `params.py`의 `YOLO_CLASSES`와 일치 필요.
