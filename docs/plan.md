## 1. 결론

- 차선 주행은 실차 1바퀴 수준. 미션 100점 중 실차에서 동작이 확인된 것은 서행 유도선(15)뿐이고 그것도 서행·판정은 미확인
- 나머지 85점은 실차 미검증. 대회용 YOLO 모델 없음(50점 + 주차 진입 의존), 주차는 어느 브랜치에서도 실차 동작 불가, 라바콘·3차선은 유경 브랜치가 main과 충돌 상태
- main 구조상 가장 큰 위험 2가지 (확인)
  1. 미션 사슬: 표지판 하나를 놓치면 이후 미션 전부 비활성
  2. 영구 정지: `fault` 상태·YOLO 예외·차선 변경 대기에서 빠져나오는 길 없음 → 15초 규정으로 해당 미션 0점 + 이후 미션 전부 0점
- 남은 기간(이동 11/17) 우선순위: 구조 2건 수정 → YOLO 모델 → 정지 미션 → 라바콘·3차선 → 주차 → 통합 반복. 차선 코드는 지금 수준에서 동결 권장

## 3. 아키텍처: 노드 하나 유지 + 구간 관리자

노드 분할은 하지 않음 (기간 부족, 현재 구조로 재생·회귀 도구가 맞춰져 있음). 바꿀 것은 미션 진행 판단 하나.

### 3.1 구간 관리자 (미션 사슬 대체)

지금: `sequence = [slow, pedestrian, fork, traffic, parking]`, 미션 **성공**해야 다음으로 넘어감.
제안: 트랙이 고정이므로 **위치**로 넘어감. 지도·SLAM 없이 두 값만 사용.

- 누적 회전각: IMU 자이로 적분. 코너 4개가 모두 우회전 90° → −90°마다 구간 번호 +1 (경계 ±25° 여유). 갈림길 45° 꺾임은 되돌아오므로 영향 없음
- 전환 보류: 라바콘 통과 중(첫 진입 ~ 종료)에는 누적 회전만 쌓고 구간은 올리지 않음. 콘이 임의 배치라 우회전을 강제하면 통과 도중 −335°를 넘어 S4로 바뀌고 라바콘이 꺼짐 (11/13 유경 영상). 종료 시점에 기준을 넘어 있으면 그때 전환, 기준 넘은 채 3 m 가면 강제 전환
- 구간 내 주행 거리: odom 속도 적분, 코너 끝에서 0으로

| 구간 | 누적 회전 | 내용 | 활성 미션 |
|---|---|---|---|
| S0 | 0° | 출발 직선 | 서행·방지턱 |
| S1 | −90° | 우측 직선 | 지그재그, 보행자 |
| S2 | −180° | 하단 직선 | 3차선, 갈림길 |
| S3 | −270° | 좌측 직선 | 라바콘 |
| S4 | −360° | 상단 안쪽 직선 | 신호등, 주차 |

- 표지판·라이다 판단은 해당 구간에서만 받음 → 오검출 억제 (광고판, 주차 칸 LIMO를 장애물로 오인 등)
- 미션을 놓쳐도 다음 구간은 정상 동작. 재출발은 구간 번호만 지정 (유경 `start_stage`와 결합)
- 왜 IMU: `/odom` 회전은 조향 명령으로 계산한 값. 실측 회전 = 0.93 × odom (11/9 측정) → 코너 유지·차선 변경·주차 회전각 모두 7% 오차

### 3.2 멈춤 방지 규칙

- `fault` 상태 제거. 시간 초과 시 차선 주행 복귀 (유경 `leave_mission` 방식)
- YOLO 예외·시간 초과 → 표지판 미션만 끄고 차선·라이다 주행 계속
- 의도한 정지(보행자·신호등 대기, 주차 완료) 외에 속도 0이 8초 넘으면 저속 전진 또는 다음 동작으로 강제 전환
- 비상 정지 거리: 지금 0.18 m는 라이다 기준 → 앞 범퍼(라이다 앞 0.16 m)에서 2 cm. 범퍼 기준으로 환산 필요

## 4. 미션별 핵심 알고리즘

### 4.1 정지 공통 (보행자 10 + 신호등 15)

1. 정지선 선택: 흰 가로선 중 **횡단보도 줄무늬 바로 앞 선**. 미션 시작선(40 mm)도 흰 가로선이라 굵기로는 구분 불가 (정지선 30 mm). 신호등 정지선은 시작선 0.88 m 뒤 (도면)
2. 거리 추적: 보일 때는 BEV 측정(영상 지연 보정, 현재 구현 유지), 앞축 앞 0.4 m 안은 odom 적분
3. 속도: `v = clip(sqrt(2·a·남은거리), v_min, 0.13)`, a ≈ 0.3 m/s², v_min = 실차에서 확실히 구르는 최저 속도(실측). 남은 거리 ≤ 허용 오차면 0
   - 왜: 지금 `남은거리 × 0.9`는 5 cm 남았을 때 0.045 m/s → 모터가 안 구르면 정지 판정에 못 들어가 시간 초과
4. 목표: 앞축이 선 앞 2 cm (넘지 않는 쪽으로 치우침). 실측 편차(+2~3 cm, 11/9)를 `stop_offset`에 반영. v3 뒷바퀴 기준이 정지선에도 적용되면 목표를 뒷축 기준으로 전환 (오프셋 −0.2 m, 2장 참고). 보행자·신호등 오프셋은 한 곳에서 바꾸게 정리
5. 보행자 대기 4.0초 (판정은 완전 정지 시점부터 3초 이상, 스톱워치 오차 대비)

### 4.2 신호등·광고판

- YOLO 상자 안에서 등 위치 확인: 상자 세로 3등분 중 가장 밝은 칸 (위 = 적, 가운데 = 황, 아래 = 녹). 색이 날아가도 위치는 유지
- 크기 일관성: 신호등 실제 크기 12×20.5 cm → 정지선 거리로 예상 상자 높이 계산, 크게 다르면 버림 (모니터 속 신호등 그림 제거)
- 3프레임 연속 일치 시 확정. 황색 = 적색 취급. 녹색 확인 후 즉시 발진 (15초 제한)
- 광고 영상이 켜진 모니터를 배경 음성 데이터로 학습에 포함

### 4.3 서행·방지턱 (10)

- 진입: `slow` 표지판 또는 S0 구간 거리(출발선에서 약 1.5 m, 도면 시작선 x 2320) 중 먼저 오는 것. 흰 마름모 검출은 3차 보조
- 속도 0.15 m/s (기본의 1/2, 육안 판정이라 차이를 분명히)
- 출발 직후부터 서행하지 않음: 육안 판정이라 0.4 → 0.15로 줄어드는 모습이 보여야 함
- 방지턱 감지: 자이로 x·y 짧은 적분 기울기 크기 2° 이상 (속도·IMU 장착 방향과 무관). 수직 가속은 저속에서 신호가 작아 미사용
- 해제 (먼저 오는 것): 첫 감지 뒤 0.5 m(뒷바퀴 통과) / 현장 실측 `exit_distance` / 1번 코너 진입 / 감속 뒤 4 m
- 방지턱 위에서는 카메라가 흔들림 → 첫 감지 뒤 0.35 m 조향 유지
- 턱에서 멈춤(실패 조건) 대비: 0.7초 안 구르면 명령 0.2 → 0.3 단계 상승, 0.1 m 구르면 0.15 복귀
- 구현: `slow_zone.py` (11/12, `feat/slow-zone`). 문턱·거리 값은 방지턱 실차 녹화로 확정 필요
- 실차 확인: 0.15 m/s로 방지턱을 넘는지, 그때 `/imu` 기울기 크기

### 4.4 서행 유도선 (15)

- 진입: S1 구간 + 선 맞춤 잔차 큼(재맞춤 전 잔차 사용) 또는 시작선 통과
- 제어 (v3로 필수): 진입 직전 직선에서 잡은 방향을 IMU로 유지. 조향 = Kp·(기준 방향 − 현재 방향) + 약한 횡 보정
- 횡 보정: 좌우 선 픽셀을 각각 **1차 직선**으로 맞춘 중앙 (톱니가 평균됨). 2차식은 톱니를 곡률로 해석
- 속도 0.15~0.2 m/s 고정, 코너 유지·곡률 감속 판단 끔. 해제: 주행 1.7 m (규정 1677 mm) 또는 잔차 정상
- 여유: 최소 폭 450 − 차폭 220 → 한쪽 11.5 cm

### 4.5 3차선 정적 장애물 (10) + 갈림길 (10)

- 차로 판단: 선 색 조합 (노랑/흰 = 왼쪽, 흰/흰 = 가운데, 흰/노랑 = 오른쪽), 현재 구현 유지
- 회피: 라이다로 차로별 빈 거리 → 더 멀리 빈 쪽 (유경 구현). 방향 표지판을 이미 읽었으면 그쪽 우선
- 한 차로 이동은 최소 약 0.8 m 필요 (R 0.45, 횡 0.52 m, 최대 조향 S자) → 여유 있게 1.2 m 앞에서 시작
- 방향·횡이동 적분은 IMU 회전 사용
- 갈림길: 표지판 확정 후 **그쪽 바깥 노란 실선을 기준으로 0.26 m 안쪽 추종**
  - 왜: 가운데 차로는 섬(x 2.5~4.2 m)에서 끝남. 바깥 노란 선은 A·B로 끊김 없이 이어지고 끝의 45° 꺾임도 그대로 따라감. 현재 차로 번호를 몰라도 수렴
  - 목적 차로가 두 칸 옆이면 도착할 때까지 차선 변경 반복
- 표지판 인식 거리 확보: 판면 Ø9 cm는 640 px 영상에서 1.5 m 거리 27 px. 320 px 추론이면 13 px → 좌우 구분 불가 → 640 px + GPU 필수

### 4.6 라바콘 (15)

- 방식: 양옆 콘 사이 중앙선 추종 (유경 방향이 주최 답변과 일치). main의 "도로 중심 쪽 통과 + 콘 간격 1 m 가정"은 배치와 안 맞음
- 보강 1: 콘 위치를 odom 고정 좌표에 누적 (최근 2 m). 왜: T-mini Pro는 10 Hz에서 점 간격 약 0.9° → 1.5 m 거리 콘(폭 4~5 cm)에 점 1~2개, 프레임마다 보였다 안 보였다 함
- 보강 2: 카메라 붉은색 마스크로 콘 바닥 위치를 BEV에서 확인. 진입 판단을 라이다 + 색 둘 다 만족으로 → 표지판 기둥·LIMO 오인 제거
- 좌우 분류: 가까운 콘부터 중앙선 연장 기준 (유경 `corridor_line`)
- 진입은 S3 구간에서만, 종료는 콘 없음 0.3 m 또는 구간 거리 초과
- 실차 확인: 실제 콘 폭·높이로 군집 폭 범위(지금 1.5~12 cm) 재설정, 콘 간 통로 폭

## 6. 코드 평가

### 6.1 잘 된 점

- 계산(`loop.py`)과 ROS 입출력(`node.py`) 분리 → 녹화 재생·합성 시나리오로 차 없이 검증 가능
- 센서 나이 검사, 영상 지연에 따른 속도 제한(`max_image_travel`), 발행 직전 한계 적용, 종료 시 0 명령
- 정지선 거리: 영상 지연 보정 + 보이지 않는 구간 odom 추적 + 먼 줄로 갈아타기 방지
- 표지판: 연속 프레임 확인, 클래스별 면적 하한, 잘린 상자 제외, 쿨다운
- 차선 인식 1회 3.5 ms (맥 측정) → 20 Hz 주기에 충분. 차선 색·흰색 분리, 실제 픽셀 기준 좌우 판단
- 수정마다 녹화 근거를 주석에 기록, 디버그 화면·재생 도구 갖춤

### 6.2 치명 (대회 전 반드시)

### 6.3 높음

- 정지 속도 곡선: 남은 거리 비례라 끝에서 0.02 m/s대 명령. 실차 최저 속도 미확인. 접근 시간 약 12초(1.5 m에서 시작 시)로 15초 제한에 근접
- 정지선 종류 구분 없음: 미션 시작선도 같은 조건으로 잡힘. 지금은 표지판 인식 거리가 짧아 우연히 맞는 구조 → 인식 거리가 늘면 엉뚱한 선에 정지
- 회전각을 `/odom`에서 받음 (명령 기반, 실측의 1.07배) → 코너 유지 65°, 차선 변경 종료 조건(방향 2° 이내), 라바콘 방향 추적에 오차
- 갈림길 차선 변경 1회만 요청 (`fork_request`) → 반대쪽 바깥 차로에 있으면 가운데 차로(섬 방향)에서 끝남
- 비상 정지 0.18 m가 라이다 기준 → 범퍼 앞 2 cm, 0.4 m/s에서는 접촉 후 정지
- YOLO CPU·320 px: 9 cm 표지판 인식 거리 약 0.8 m 이내 (추정, 실측 필요)
- `robot.yaml` 실측 안 된 값: 라이다 x·z, 카메라 x, 차 폭·길이 → 라바콘·주차 여유 계산에 직접 영향

### 6.4 중간

- 회귀 시험이 미션을 검증하지 못하는 상태 (확인): 시나리오 정지선이 노랑이라 흰색 검출 이후 상태가 `lane` 하나뿐, 기준값도 불일치(3084 vs 3096). 정지선을 흰색으로 그리면 보행자 → 차선 변경 → 신호등 → 주차 전 과정 진행됨 → 시나리오 수정 + 표지판 누락 경우 추가
- 차선 코드 복잡도: 코너 유지에 시작 조건 5개·조향 2종·건너뛰기 창 등 녹화별 예외가 누적. 통과는 하나 시작 시점에 민감(11/9~10 실차 기록), 수정이 다른 코너를 깨뜨린 이력 → 구조 변경 없이 동결하고 IMU 회전만 교체 권장
- 서행 유도선 전용 처리 없음: 서행은 `abnormal`(재맞춤 후 잔차) 판정에 의존 → 보장 안 됨
- 서행 해제가 시간(14초) 기준, 보행자 대기 3.2초로 여유 적음
- `driver.py`에 정지선·표지판·갈림길·최종 선택이 한 클래스 → 팀원 동시 수정 충돌 지점
- `params.py` 키 검사 없음, 코드 내 상수 잔존

### 6.5 효율

- 제어 20 Hz, 차선 3.5 ms(맥): 문제 없음
- 병목은 YOLO (CPU 5 Hz). Jetson GPU 미사용
- main 라바콘 탐색 3,267 경로 × 35단계 순수 파이썬 루프: 유경 방식(후보 33개)으로 대체되면 해소
